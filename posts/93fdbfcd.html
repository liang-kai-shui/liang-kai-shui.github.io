底图、封面，还有一个转圈的 bug

发表于 2026-09-10| 更新于 2026-09-10| 折腾记录
总字数: 1.7k| 阅读时长: 6分钟| 浏览量: —

这周打开博客的次数比写文章还多。先是刷底图时老看见那几张熟面孔，接着又被一堆没整理的封面图绊住；改完这些，侧栏的访问量还一直转圈。索性把三件事都记下来。

底图：从自己的图池换成别人的接口

上个月我给站子加过“每次刷新换底图”的功能，做法是在图床里存 60 张图，前端每次随机取一张。用了一阵子发现不太行：60 张其实不多，刷几十次就开始重复，而且那批图是随机挑的，里面有几张我自己看着都别扭。

后来翻到一个二次元随机图接口，栗次元（t.alcy.cc），免费、不用注册，接口挺多：

接口 内容
/ycy 二次元自适应（桌面横图、手机竖图自动判断）
/pc PC 横图
/mp 手机竖图
/acg ACG 动图

我一开始想当然，以为 /acg 也是返回一张图片，直接当 CSS 背景写上去，测的时候背景一片黑。用 curl 看了一眼才知道它跳过去的是 mp4：

curl -I https://t.alcy.cc/acg
# HTTP/1.1 302 Found
# Location: /pic/acg/83863.mp4

一条动图 4.7 MB，塞不进 background-image。所以动图单独处理，在背景层里挂了个 <video muted loop playsinline>，用 object-fit: cover 铺满。顺手把它的抽中概率压到七分之一，不然刷几次就下 5 MB；系统开了“减少动态效果”或者浏览器开了省流量模式的时候直接跳过。

另一个坑是缓存。这几个接口都是 302 跳转，浏览器会把跳转结果缓存住 —— 我连续刷了 6 次都是同一张图，当时还以为是接口写死了。请求上带个随机参数就好了：

https://t.alcy.cc/pc?r=x8k2m1

现在桌面端在 /ycy、/pc、/acg 三个接口里按权重随机挑，手机端（屏幕宽度 768 以下）固定用 /mp 竖图。之前那 60 张图池没删，接口出问题时会退回去用它。

调试时留了个手动开关：网址后面加 ?bg=pc 只出横图，?bg=off 完全不换。

封面：让新文章自己去拿一张

起因是攒图。想给以后的文章留点封面素材，就往一个文件夹里丢图，断断续续丢了一百来张（后来一看 523 MB）。

本来只是放着备用，但每次写文章都要翻图、下载、转格式、传图床、再把地址粘进 front-matter，四五步，烦。索性做成一键：图丢进 bg-inbox/，跑一条命令，脚本转 webp、按编号传到图床、登记进封面池。

npm run cover:add

100 个文件里有 1 组内容完全相同（Windows 复制出来的”- 副本 - 副本”），脚本按文件内容算哈希去掉了，最后上传 97 张，一共 16 MB。

之后新建文章不用再管封面：

npm run new -- "文章标题"

建完自动从封面池里挑一张还没用过的，写进 front-matter。

这块我绕了远路。一开始想的是“构建的时候自动加”，连 front-matter 都不用写，听着比较优雅。试了三种写法：

before_generate 里 post.cover = url
before_generate 里 post.set('cover', url)
before_post_render 里 data.cover = url

日志全都打印“赋值成功”，页面渲染出来还是主题默认的那张 p17。查了半天才明白：Hexo 的文章对象对没在 schema 里声明过的字段不做持久化，我在这一处改了对象，生成阶段读出来的是另一个对象，属性没了；而且主题自己有个生成器，文章没有 cover 时会先填上默认值。

改成直接写进 front-matter，一次就对了。回头看这个选择本身也更合适：封面是什么，打开文章文件就能看见，想换随手改，不用去猜哪一层把值覆盖掉了。

一个转圈的 bug

你如果前几天打开过首页，侧栏“网站信息”里有两行是转圈的：总访问量、访客数，一直转，出不来。文章页里的“阅读量”倒正常。

先怀疑接口。手动打了一下：

curl https://comments.lksme.dpdns.org/api/stats
{"ok":true,"data":{"site_pv":19,"pages":5,"site_uv":6,"today_pv":19,"comments":3}}

接口没问题。打开控制台，看到一行：

[stats] 没有配置后端地址（lks_comment.api），统计与反应不启用

原来是取不到后端地址，脚本直接不干活了。为什么首页取不到？因为这个地址之前是评论组件那段模板注入的，只有渲染了评论区的页面才会走到那段代码 —— 首页、归档、标签这些列表页没有评论区，自然也没有地址。文章页有评论区，所以阅读量正常。症状对上了。

改法是把地址挪到全站注入，写在 scripts/inject-client-config.js。这里又踩了两个坑，记一下：

两个坑的具体样子

一、取配置的时机。 最初我在注入阶段读 hexo.theme.config.lks_comment，拿到的是 undefined。主题的 merge_config 在 before_generate（优先级 1）把合并结果写进 theme.config，但到渲染收尾时它已经变回主题自带的 _config.yml 了，那里面没有 lks_comment 这种自定义键。所以得在 before_generate（优先级放到 25，晚于主题的合并）先把值缓存下来。

二、injector.register 的求值时机。 我本来用 hexo.extend.injector.register('head_end', () => ...)，结果注入出来是空字符串。加了一行日志看顺序才发现：这个内容函数在注册的时候就被调用了，不是在每页渲染时，那会儿缓存还是空的。换成 after_render:html 过滤器逐页拼接，就正常了。

顺手把另一个情况也修了：万一接口真的挂了，或者被浏览器插件挡住，前端原来会一直转下去。现在请求失败、或者 8 秒还没结果，就写一个破折号，总比让人盯着一个转圈的图标强。

另外记两笔

  • 把 GitHub Actions 里的 action 升到 v7、Node 升到 24，之前每次跑都提示 Node 20 已弃用。
  • bg-inbox/ 里那 98 张原图现在可以删了。封面都传上去并且在 source/_data/covers.yml 里登记过，重复跑也不会重复加。
  • 底图池那 60 张留在图床当兜底，暂时不打算删。

现在我最希望有人帮忙留意的，反倒是那个不起眼的破折号：如果统计接口又出问题，它应该出现，而不是让数字一直转下去。看到异常可以在留言板告诉我是哪一页。
