留言板终于能留言了：自建评论系统记录

发表于2026-09-10|更新于2026-09-10|折腾记录
|总字数:2.2k|阅读时长:7分钟|浏览量:

想说的话，总得有个地方落下来。

留言板挂了很久了 —— 准确说，它一直”看起来”是好的：页面打开有个挺好看的信封，写着「来自凉开水的留言」，就是没有任何地方能输入。这篇记录一下我把它彻底修好、并且顺手把评论数据揣回自己兜里的过程。

一、先说结论

现在留言板、每篇文章底部都有评论框了。不需要登录任何账号，填个昵称就能发；数据存在我自己的 Cloudflare 数据库里，不经过第三方评论服务。

后端是一个自己写的小 Worker，代码就在博客仓库的 comment-worker/ 目录里 —— 换句话说，这套东西的源码和文章放在一起，不会再有”服务商跑路我就抓瞎”的问题。

二、为什么留言板留不了言

排查下来是两个原因叠在一起：

  1. 那个信封是纯装饰。 /comments/ 页面是 hexo-butterfly-envelope 插件生成的，我翻了插件源码，它渲染出来的表单长这样：

pointer-events: none —— 整个表单不可交互，它只负责画个信封、写几句”有什么想说的”。

  1. 真正的评论框没被启用。 能输入、能提交的评论框由主题的评论系统渲染，而配置文件里 comments.use 是空的。没有评论系统 → 没有评论框 → 自然也谈不上后端。

所以严格说，留言板不是”坏了”，是从来没接上过。

三、试过的三条路，都不太顺

静态博客自己存不了数据，”能留言”靠的是把数据存到别处。我先试了三条现成的路：

方案 结果
Waline + 腾讯云 CloudBase 一键部署 ✗ 我这边的腾讯云环境建不了 CloudBase，那个”一键部署”按钮点下去走不通
Waline + Vercel + Neon 数据库 ✗ 要注册两个账号，而且 Vercel 在国内访问一般
Giscus / Utterances（基于 GitHub） ✗ 零后端确实最省事，但留言的人必须登录 GitHub —— 普通朋友基本不会为留一句话去注册账号

Waline 官方也不支持部署到 Cloudflare Workers，那条捷径也堵着。

四、最后为什么自己写

绕一圈发现，我缺的其实不是”评论系统”，是一个能存数据的地方。而这个地方我早就有了：

图床 pic-bed-e0x.pages.dev 就跑在 Cloudflare Pages 上 —— 说明我本来就有 Cloudflare 账号。

那就用 Cloudflare Workers + D1（D1 是 Cloudflare 的 SQL 数据库）：
免费额度每天 10 万次请求、5GB 存储，个人博客连零头都用不到；不用备案、不用买服务器；而且访客匿名留言，不需要注册任何账号。

前端放在博客里（source/js/comment.js），后端是一个单独的 Worker，两边靠 HTTP 接口说话。

五、它是怎么工作的

接口不多，够用就行：

接口 干什么
GET /api/comments?path=... 取某篇文章的评论（只返回审核通过的）
POST /api/comments 发一条评论，支持回复
GET /api/count、GET /api/recent 评论数、全站最新评论（侧边栏那张卡片）
DELETE /api/comments/:id 删除（软删，需要管理口令）
GET /admin 一个简易管理页面：搜索、删除、通过待审核

数据库五张表，各管一摊：

表 存什么
comments 评论本体（含 status：正常 / 待审核 / 已删除）
pageviews + pv_log 每篇文章的浏览量 + 去重日志
reactions + reaction_log 文章点赞数 + 去重日志

两个小设计

去重：同一 IP 对同一篇文章，浏览量每小时只算一次、同一种点赞每天只算一次 —— 免得有人按 F5 把数字顶上天。

隐私：数据库里不存明文 IP，只存 sha256(IP + 随机盐) 的前 32 位，用途仅限限流；邮箱只有我自己在管理后台看得到，前台接口根本不返回这个字段。

六、防刷四件套

留言板一旦公开，最先来的往往是广告机器人。现在有四层：

手段 说明
蜜罐字段 表单里有个真人看不见的输入框，机器人爱填 —— 填了就假装成功、实际丢弃
限流 同一 IP 每分钟 1 条、每天 20 条
含链接进待审核 带链接的评论先隐藏，我在后台点了”通过”才显示（广告九成都带链接）
Turnstile（可选） Cloudflare 的免费人机验证，需要时在配置里填个 sitekey 就会出现

七、顺手做的两件事

既然后端有了，同一套东西还能干点别的：

① 自己统计浏览量。 原来用的是 busuanzi，但它的域名在国内经常超时，数字时有时无。现在换成自己的接口了。

这里有个取巧但挺妙的处理

busuanzi 在页面上的显示位置，主题是用固定 id 写死的：

关掉 busuanzi 插件会让这些元素消失，页面结构就跟原来不一样了。所以我没改主题模板，而是把 busuanzi 的脚本换成一个空文件，元素 id 保持原样，再让自己写的统计脚本往同样的元素里填数据 —— 页面结构不变、只有一个数据写入方，两套数字不会打架。

② 文章点赞。 文章底部多了三个按钮：👍 有用 / 💡 学到了 / ❤️ 喜欢。留评论的门槛比点赞高得多，这个基本是顺手点的。

八、踩过的坑

本地起 Waline 服务端做测试，卡死

想在本地先跑通一遍再动线上，结果 wrangler dev 里那套 Waline 服务端在 Node 26 上直接卡住不响应 —— 追下去是它依赖的原生 SQLite 模块没有 Node 26 的预编译包。

后来想通了：我本来就不需要本地跑 Waline，我用的是自己写的 Worker，本地用 wrangler 自带的 D1 模拟就能测，没必要绕那一圈。

侧边栏「最新评论」卡片一直显示"加载中"

主题自带的几个评论后端，都是把初始化挂在 window 的 load 事件上。而页面里有一堆 CDN 资源，在国内经常加载得很慢 —— load 事件被拖到十几秒甚至更久才触发，卡片就一直停在”加载中”。

改成”DOM 就绪就执行”就好了。顺带把这习惯带进了自己的脚本：能用 DOMContentLoaded 就别等 load。

测试自己的限流把测试自己挡住了

写自动化测试的时候连着发两条评论，第二条被限流挡了 —— 因为限流是”每分钟 1 条”。测试里手动放宽了限制才跑通。

这个坑提醒我：限流这类策略要能配置，不然测试和维护都会很别扭。

假失败：国内网络下"页面没加载完"被我判成了"功能坏了"

线上自检脚本原来固定等 6 秒就下结论，结果经常报”评论列表是空的” —— 其实只是页面 JS 还没跑起来。

改成轮询等待（最多 45 秒）之后就稳了。别用固定 sleep 判断异步结果，这是我这轮学到最实用的一条。

九、成本、备份和管理

  • 成本：目前是 0 元。免费额度是每天 10 万次请求，我这个量级大概用掉几百分之一。
  • 备份：评论都在 Cloudflare 的 D1 里，一条命令导出：
  • 管理：打开 https://comments.lksme.dpdns.org/admin，输管理口令就能删评论、通过待审核、按关键词搜索。
  • 换域名不影响评论：评论是按页面路径存的，跟域名无关。

十、写在最后

现在留言板是通的：不用登录、不用等审核（不带链接的话）、填个昵称就能说话。

技术上没什么高深的东西，就是一个 Worker 加五张表。真正的收获是两件事：

  1. 遇到”现成方案都用不了”的时候，先想清楚自己缺的到底是什么 —— 我缺的只是”一个能存数据的地方”，而不是”一个评论系统”。
  2. 静态站不等于没有动态能力。静态只是说页面是预先生成好的，它照样可以调用接口、写数据库、做点赞和统计。

要是你在留言时发现哪里不对劲，欢迎就地吐槽 —— 通道现在是通的 😉
