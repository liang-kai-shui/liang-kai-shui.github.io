写了一份 C++ 讲义，第一章不讲代码

发表于2026-10-02|更新于2026-10-02|折腾记录
|总字数:2.5k|阅读时长:7分钟|浏览量:

最近在写一份 C++ 零基础讲义，配《C++ Primer Plus（第 6 版）》用。写到第 4 章，第一章却一行代码都没有。网页版放在这里：

https://lksme.dpdns.org/cpp-primer-plus-course/

目前 1 到 4 章（4 章内容多，拆成了 A、B、C、D，A 和 B 完成了）写完，全书 18 章，后面还在写。

为什么第一章没写代码

这份材料有一条自己定的规矩：

每个专有名词第一次出现的时候，必须先说清楚三件事：

  1. 这是什么（用一句人话）
  2. 为什么需要它（它解决了什么问题，没它会怎样）
  3. 打个比方（用生活里的东西类比）

然后才往下讲怎么用。

这条规矩不是我凭空想的，是被人问烦了总结出来的。太多课（包括学校里的）是这么讲的：一上来就是”变量””函数””编译””指针”，但不讲它是什么、为什么需要它、它怎么实现的。听完的感觉不是”我懂了”，是”我是不是太笨了”。

照这个规矩写下去，原来的大纲很快就不够用了。第 1 章写完，一行代码都没出现。

那一章我写的目标是”学完能用自己的话回答这 6 个问题”，比如：

  • 源代码、编译器、可执行文件是什么关系？
  • 从 demo.cpp 到 demo.exe，中间到底经过了哪四步？每一步产出什么文件？
  • 编译错误、链接错误、运行时错误怎么区分？各自往哪个方向排查？
  • 为什么”能编译通过”完全不代表”程序是对的”？

最后这条是那一章的隐藏重点。一个能跑的程序和一个正确的程序，是两回事。 这句话后面每一课都要用到。

在变量之前，先说清楚「文件」

我在这份材料最前面加了一篇《零基础起飞：电脑与编程的最基本概念》，两万两千多字，读完大概半小时。它讲的是那些”一般教程默认你会、但其实从来没讲过”的东西：

  • CPU、内存、硬盘分别是什么。这里用的是厨房的比方：CPU 是灶台和炒锅，内存是料理台面，硬盘是冰箱和储物柜。最关键的一句是”CPU 只会算，但它自己不记得任何东西，要算的东西得先从柜子搬到台面上”。
  • 什么是文件、什么是文件夹、什么是路径，以及怎么把 Windows 隐藏的文件扩展名显示出来（这一步不做，后面 demo.cpp 和 demo.txt 长得一模一样，肉眼分不出来）。
  • 什么是程序、什么是进程、任务管理器怎么打开。
  • 什么是编译器、什么是命令行。
  • 为什么中文会乱码，以及为什么”改了代码运行结果没变”。

最后这两个问题几乎每个新手都会撞上，而且撞上之后基本都会怀疑人生。乱码的原因和控制台的”代码页”有关，讲清楚之后就不是玄学了；”改了没变”通常是编译没成功或者跑的还是旧的可执行文件。

有这篇打底，后面讲变量的地方就不用停下来解释”文件是什么”了。

让编译器真的报几次错

示例代码/01_错误分类实验/ 里放了六个文件，你可以直接编译它们，然后看编译器怎么骂你：

光背「编译错误」「运行时错误」没什么用，动手跑一遍才知道区别：少分号和类型不匹配会卡在编译阶段；未定义的函数还可能到链接阶段才报错；多写一个分号反而可能顺利通过。除零要看运行时的实际表现，数组越界更麻烦，程序未必立刻报错，却已经不能相信结果了。

顺带教一件事：报错先从前面读，找到第一条与自己代码有关的错误。新手很容易直接拖到最下面，只看到「构建失败」之类的汇总，真正有用的文件名和行号反而被略过去了。

教材只标页码

讲义里到处是”教材 pXX”，但那套教材（253MB 的 PDF）不在仓库里。

我试过放进去。git add 之后才注意到两件事：一是它 253MB，二是这个仓库的 docs/ 目录是 GitHub Pages 的根目录，所以它会同时被放两份（一份在根目录给读者，一份在 docs/ 给网页版）。提交信息都写好了，叫”添加原书”，然后我把它撤了。

撤回之后 .git 里还留着那次的痕迹：一个悬空的提交，加一个 220MB 的对象。它不在任何分支上，所以没推上去，但那 220MB 是真占着本地磁盘的，得等 git gc 才收回去。

现在的做法是只标页码：讲义里写”读 p18–p28””1.4 节精读三遍”，读者拿自己手上的 PDF 去翻。干净，也不用碰版权。

顺便说一句，那套教材自己是有印刷错误的。第 3 章编程练习 7 里有个换算因子就印错了。所以材料里专门提醒过：遇到和教材对不上的地方，先用例子验证公式，别先怀疑自己。

网页版怎么生成的

在线阅读那个站点是 tools/build_html.py 从 Markdown 生成出来的，20 个 md 文件进，一套自带样式的 HTML 出来。

生成的页面不依赖网络：CSS、JS、代码高亮全内联在文件里，拷到 U 盘、发给别人、断网双击都能看。另外有两种版本，一个是带侧边导航的在线版，一个是 全一册.html（1.1MB 单文件，把所有内容拼在一起，最方便转发）。

这个脚本也留下了几个坑：

markdown 自带的 slugify 会把中文全部剥掉。 ## 本课目标 生成的锚点 id 是空字符串（然后被去重成 _1），## 1.1 人和计算机 变成 11。后果不只是难看：材料里那些手写的 GitHub 风格锚点（#1-电脑到底在干什么）全都对不上。解决办法是自己写一个 slugify，保留中文，只剥标点。

代码高亮配色要按主题隔离。 一开始图省事用了 pygments 的内联颜色，结果深色模式下代码块是浅色底，白得刺眼。正确做法是输出两套 CSS，一套作用域挂在 [data-theme="dark"] .codehilite 上，一套挂在 [data-theme="light"] 上，切换主题时跟着换。

“全一册”把所有页面拍平到一个文件里，相对链接全废。 讲义页里写的是 ../附录/术语表.html，单独看没问题，但拍平之后就指向了一个不存在的位置。所以生成单文件版时要先把每个链接按它原来所在的目录解析一遍，再重新写出来。

子目录页面的导航链接忘了加相对前缀。 这个 bug 的表现特别干脆：首页一切正常，点进任何子目录的页面，导航里点什么都不动了，全是 404。原因是导航的 href 是相对当前页面的，子目录页面要用 ../。修好之后我把原因直接写进注释了，免得下次又踩。

还有个小的：术语表有 100 多条词条，自动生成的”本页目录”长到快把正文挤下去了。所以超过 25 项就折进一个 <details> 里，点开才展开。

两个地址，同一份内容

这套材料有两个地址：

  • https://liang-kai-shui.github.io/cpp-primer-plus-course/ 这是仓库自己的 GitHub Pages 项目页
  • https://lksme.dpdns.org/cpp-primer-plus-course/ 这是主站域名下的同一个路径

第二个能用，是因为主站（这个博客）绑了自定义域名，GitHub Pages 会把同一个账号下所有项目页也放到那个域名下面。所以同一份文件，两个地址都能进，实测都是 200。这也意味着读者不需要记两个网址。

目前写到哪里了

部分 规模
讲义（第 1–4 章 A/B） 5 份，约 15.5 万字
术语表 1 份，约 4.5 万字，100+ 词条
练习 5 套，含教材原题和动手实验
参考答案 40 个文件（复习题答案 + 编程练习代码 + 实验代码）
示例代码 33 个 .cpp，都能直接编译

几条定下来的规矩：

  • 代码 MIT，文档 CC BY-NC-SA 4.0。 代码随便拿去用；讲义可以转载，但别拿去卖，转的时候注明出处。
  • 练习里的题目文字是转抄自教材的（为了方便读者对照着做题），著作权归原作者和出版方，只做教学用。这一条在仓库里写明了，如果权利人觉得不妥，开个 issue 我就删。
  • 参考答案里有一部分是学习者自己做出来的，征得同意之后收进来的。
  • 五条学习纪律里我最想强调两条：代码必须手敲（复制粘贴等于没学）；改完 bug 要用工具验证，不要用眼睛看。人是看不见”少了一个字母”的，自己写的代码尤其如此。Linux 上用 diff，Windows 上用 Compare-Object 或者 fc。

讲义还没写完，前四章也会继续改。如果某一段突然冒出一个没解释过的词，或者例子看完还是不懂，可以在仓库开个 issue，告诉我具体卡在哪一段。
