两个新按钮，和它们带来的三个 bug

发表于 2026-09-11| 更新于 2026-09-11| 折腾记录
总字数: 1.7k| 阅读时长: 6分钟| 浏览量: —

朋友说找不到夜间模式开关。我打开首页试了一下，鼠标移到右下角齿轮，再从弹出来的一排图标里认月亮，确实绕。手机上连「移上去」这一步都没有。

先把夜间模式挪出来

主题的夜间模式按钮藏在右下角那个齿轮里，得先把鼠标移上去才露出来，露出来之后还要在一排图标里找哪一个是它。手机上没有 hover，更麻烦。

现在挪到导航栏搜索图标旁边常显了，图标跟着当前模式在月亮和太阳之间换，鼠标放上去有提示。

顺手把自动切换开了（darkmode.autoChangeMode: 1）：

  • 电脑或手机自己开了深色模式，进站就是深色；
  • 系统没表态的话，晚上 18 点到早上 6 点自动切成深色；
  • 自己手动点过之后，以点的为准，下次进站不再自动切。

实现上我偷了个懒，但这个懒偷得对：切换逻辑我一行没写，只是让主题自己的按钮替我挨一下。

document.getElementById('darkmode').click()

主题那边接到点击会切 data-theme、弹个提示、把选择写进 localStorage。我要是再自己维护一份状态，两边迟早不一致。唯一要小心的是图标得等它改完 data-theme 再读，所以套了个 setTimeout(syncIcon, 0)。

骰子按钮

旁边加了个骰子，点一下随机跳一篇文章。文章清单是构建的时候生成的 /posts-index.json，每篇只存标题和链接，一共 5 篇。点的时候才去拉，拉过一次就放在内存里，不再重复请求。

两个小细节：随机到自己正在看的那篇会重抽，最多试 5 次；清单还没到的时候按钮透明度压到 0.5。键盘的 Enter 和空格也能按。

评论表情

评论框里加了个表情选择器，30 个，两行 emoji 加一行颜文字。

插进去的位置是光标所在处，不是直接追加到末尾。别小看这个，之前想在一句话中间插个表情，只能先删到那儿再重新打字。

这段没什么故事，唯一要想一下的是回复框是动态生成的，绑事件得绑在生成之后。

按钮加上去之后

一、首页点得动，点进文章就点不动

有朋友反馈的：晚上那个月亮图标，在首页点一下能切，点进任何一篇文章再点就没反应了。

第一反应是按钮被别的东西盖住了，调 z-index，没用。也怀疑过事件没绑上，可是首页明明能用。

真正的线索是右下角那个主题自带的夜间按钮，同一个页面、同一个功能，它一直是好的。区别在于它在 #rightside 里，而 #rightside 在 pjax 的容器外面。导航栏那一段是会被 pjax 整段换掉的。

我绑监听器的写法是：

document.getElementById('lks-darkmode-button').addEventListener('click', toggleTheme)

pjax 一跳转，导航栏那段 DOM 换成新的，旧元素连同它身上的监听器一起被丢掉，新按钮上什么都没有。第一次进站是首页，页面是完整加载的，所以一切正常；只要点了站内链接，按钮就废了。

改成在 document 上做事件委托，转发给这个 id。以后往导航栏加东西，监听器一律绑 document，不绑元素本身。

二、下划线歪了

两个新按钮鼠标移上去会有一条下划线，我加完发现它比图标长，还往左偏了一截。

主题的下划线是这么写的：

.site-page:not(.child):after {
  left: 0;
  width: 100%;
}

它贴着 .site-page 自己的框画。而我把和搜索图标之间的间距加在了 .site-page 上（padding-left: 14px），框被撑宽了 14px，下划线跟着一起变长左偏。

去看主题自己的搜索按钮怎么写的，间距是加在外层容器上的。照抄，对齐了。用无头浏览器量了一下：按钮盒子宽 18px、图标宽 18px，两者底边都在 47px。

三、typed is not defined

这个不是我改出来的，是主题原版的 bug，但被我新加的一条检查项抓出来了。

我在线上自检脚本里加了一项：从首页点一篇文章走 pjax，然后看控制台有没有报错。跑出来两条红的，其中一条是：

ReferenceError: typed is not defined
    at typedDestroy (utils.js:290)

首页那个打字的副标题，主题注册了一个 pjax 离开页面时的清理函数，里面直接调 window.typed.destroy()。问题在于 typed 这个变量只在 subtitle.effect: false 的时候才会创建，而我这里配的是 effect: true，它压根不存在。也就是说每次从首页点进文章，控制台都会红一条，主题原版就这样，只是不一定有人看控制台。

加了个存在性判断就好了。

中间还栽在 pug 上一次：

pug 的注释坑

我改的是主题模板里的一个 script. 块，顺手写了行 //- 注释解释为什么加这个判断。结果 pug 把注释原样输出了，注释里那句 { typed.destroy() } 变成了一行真的会执行的代码。

//- 在 pug 里是模板注释，写在这个块外面没问题。写在 script. 里，那一段会被当成脚本内容原样吐出去。

顺手发现，但这次没修

主题里还有一个同款问题，在处理系统深浅色切换的地方：

mediaQueryDark.addEventListener('change', () => {
  if (saveToLocal.get('theme') === undefined) {
    e.matches ? activateDarkMode() : activateLightMode()
  }
})

回调函数没接参数，里面的 e 是未定义的。触发条件挺具体：没手动切过模式的人，在看页面的时候系统自己切了深浅色，这时候会报错，页面也不会跟着变。我这种手动点过的反而不受影响。

修法就是加个参数，一行的事。但它属于主题文件，改完要重新打补丁、还要过一遍还原度校验，先记下来，等下次动主题的时候一起改。

改完再点一遍

改的这几处都在「每页都会有」的区块里，所以外观比对会比较麻烦。用无头浏览器测了 20 项，其中一项专门测 pjax 之后点月亮还灵不灵，结果是 dark -> light。线上自检 34 项全过，包括控制台报错那一项。

跟原站产物的逐字节还原度校验保持在 4/8 主体一致 + 4 个登记项，退出码 0。

这次最有用的测试不是数按钮有几个，而是从首页点进文章，再回头点月亮。第一次加载时好好的，不代表站内跳转之后也好好的。要是你又碰到哪个按钮点不动，留言告诉我页面地址。
