如何在 VS Code 中配置 C++ 编译环境

发表于 2026-10-03| 更新于 2026-10-03| 教程
总字数: 1.5k| 阅读时长: 5分钟| 浏览量: —

我在 C++ 讲义第一章讲过“编译器是什么”，但那篇没带人把编译器装进电脑。打开 VS Code 能写代码，点运行却可能提示找不到 g++：VS Code 是编辑器，本身不带编译器。这篇把安装、运行、打断点的过程接上。

下面按 Windows 的 64 位电脑来走。我这台机器已经有一套 MinGW-w64：g++ 在 C:\MinGW64\mingw64\bin，gdb 也在同一个目录。下文就用这个实际路径；你装的版本可以不同，只要找到自己那套 bin 文件夹就行。

先把编译器装好

从官网装 VS Code，再在扩展商店搜索 C/C++，装发布者为 Microsoft 的那个扩展。扩展提供补全、错误提示和调试入口，仍然不等于编译器。VS Code 放在 C 盘或别的盘都可以，不用为了这一步特意搬位置。

如果你已经装过 MinGW64，先去它的 bin 目录看看有没有 g++.exe 和 gdb.exe，有就不用重装。我的目录是 C:\MinGW64\mingw64\bin，本机显示 GCC 8.1.0、GDB 8.1。这是现有环境，不是让你专门去找 8.1.0 的老包。

从零安装的话，可以从 mingw-w64 官网列出的预编译工具链里选 Windows 64 位、同时带 GCC 和 GDB 的压缩包。例如页面列出的 WinLibs 提供可直接解压的版本，里面也有 mingw64\bin。解压后先用资源管理器找到实际的 g++.exe：多套一层文件夹很常见，别只凭压缩包名字猜路径。下面统一假设它在 C:\MinGW64\mingw64\bin，你的路径不同就按实际位置替换。

让 VS Code 找得到它

编译器虽然已经躺在磁盘里，普通终端和 VS Code 还未必能找到它。打开 Windows 搜索，输入“编辑账户的环境变量”，在用户变量里找到 Path，点“编辑”→“新建”，加入：

C:\MinGW64\mingw64\bin

加的是 bin 文件夹，不是 C:\MinGW64。确定保存后，把已经打开的 VS Code 和终端都关掉，再重新打开。旧窗口不会自动读到新的 Path。

在新开的 PowerShell（VS Code 内置终端也行）里检查：

where.exe g++
where.exe gdb
g++ --version
gdb --version

前两条应该指向 C:\MinGW64\mingw64\bin；我在这台电脑上查到的就是这两条路径。如果 where.exe g++ 先列出另一套编译器，调整 Path 里旧目录的位置，再开一个新终端检查。编译和调试尽量用同一套 bin 里的 g++、gdb，不要混着选。

先在终端编译一次

建一个空文件夹，用 VS Code 的“文件 → 打开文件夹”打开它，然后新建 hello.cpp：

#include <iostream>

int main() {
    std::cout << "Hello, C++!\n";
    return 0;
}

先按 Ctrl+S 保存。打开 VS Code 的终端，确认它当前就在这个文件夹里，然后执行：

g++ -std=c++17 -Wall -Wextra -g hello.cpp -o hello.exe
.\hello.exe

看到 Hello, C++! 就说明编译和运行这两段已经通了。第一行把 .cpp 编译成 .exe，其中 -g 留下调试信息；第二行运行刚生成的程序。PowerShell 里运行当前目录的程序要加 . 和反斜杠，所以这里是 .\hello.exe。

这一关值得单独做：如果终端里的 g++ 都没法编译，反复点 VS Code 右上角的三角形也不会解决问题。

再用 VS Code 的按钮运行和调试

保持 hello.cpp 是当前打开的文件，点编辑器右上角的运行按钮。第一次会让你选编译器，选 C/C++: g++.exe build and debug active file，注意路径应当是 C:\MinGW64\mingw64\bin\g++.exe。成功后，输出会出现在下方终端里。

想试断点，就在 std::cout 那行左边点一下，让行号旁边出现红点，再从运行按钮旁的下拉菜单选 Debug C/C++ File。程序停住后可以看变量、单步执行；按 F5 继续。

VS Code 通常会在文件夹里生成 .vscode/tasks.json 来记住编译命令。刚学的时候不用照网上的帖子抄一大段 tasks.json 和 launch.json；先让自动生成的配置跑通。等需要传命令行参数、编译多个源文件时，再改这些文件。

如果卡住了，先看是哪一层

  • g++ 不是命令：回去看 Path 有没有写到 C:\MinGW64\mingw64\bin，然后重开终端。用 where.exe g++ 看 Windows 实际找到了哪个文件。
  • 能编译，调试时说找不到 gdb：用 where.exe gdb 检查。如果压缩包里根本没有 gdb.exe，换一份包含 GDB 的完整工具链；如果文件在但 VS Code 仍找不到，在 .vscode/launch.json 的调试配置里写上 "miDebuggerPath": "C:\\MinGW64\\mingw64\\bin\\gdb.exe"。这里的双反斜杠是 JSON 的写法。
  • 代码能编译，但 #include <iostream> 下面有红线：这通常是编辑器的补全配置没找到编译器。在命令面板里搜 C/C++: Select IntelliSense Configuration，选 C:\MinGW64\mingw64\bin\g++.exe。补全提示和真实编译是两套环节，别只靠红线判断程序能不能跑。
  • 改了代码，运行结果还是旧的：先看编译那一步有没有报错。编译失败不会生成新的 .exe，你点开的可能仍是上次编译出来的旧文件。
  • 代码拆成了好几个 .cpp，出现 undefined reference：右上角默认配置只编译当前文件。可以先在终端明确写出所有源文件，例如 g++ main.cpp helper.cpp -o app.exe；文件多了再考虑 CMake。

我建议把第一次输出先写成英文的 Hello, C++!。如果它能正常显示，后面中文输出乱码就单独排查终端编码，不用从头重装编译器。

能在终端编译出 hello.exe，也能在 VS Code 里停住断点，这套环境就够用了。接下来可以开始写程序；如果还没学过 C++ 语法，我正在写的零基础讲义可以接着看。
